## Current recommendation

### Raw archive required

- `opencode.db`: primary SQLite database; required for visible transcript extraction and stores session, message, part, project, todo, reasoning, tool, cost, and token records.
- `opencode.db-wal`: required when present unless Chatlas implements a SQLite-aware backup/checkpoint step. The live main DB alone currently has fewer records than DB+WAL.
- `storage/session_diff/*.json`: per-session file diff artifacts. Retain as session-bound behavioral and workspace-change evidence.
- `tool-output/tool_*`: externalized tool-output payloads referenced by database part records. Retain until proven fully duplicated in `opencode.db`.

### Raw archive optional future

- No separate OpenCode optional raw family is recommended right now. Keep the archive narrow until specific non-required evidence proves useful.

### Telemetry outside session scope

- No distinct account-level quota, billing, or usage-limit file family was found under `/Users/pereiro/.local/share/opencode`.
- Session-local cost and token telemetry is already inside `opencode.db` part records, especially `step-finish` parts.

### Exclude

- `auth.json`: authentication material. Live and committed raw both contain provider entries with token-shaped fields such as access, refresh, and expiry metadata.
- `log/`: large runtime logs. They duplicate or exceed session evidence, include token-shaped matches, and are not needed by current extraction.
- `snapshot/`: OpenCode-managed Git snapshots and workspace state. This is copied project state, not primary chat evidence.
- `opencode.db-shm`: SQLite shared-memory sidecar. It is runtime state and can be rebuilt from DB+WAL.
- `storage/migration`: 1-byte migration marker with no session value.
- `bin/`: runtime/package payload area. Currently empty in the live home and should remain outside raw retention if populated.

## Suggested retention changes

- Add an OpenCode-specific raw policy instead of broad home mirroring.
- Recommended immediate include set:
  - `opencode.db`
  - `opencode.db-wal`
  - `storage/session_diff/*.json`
  - `tool-output/tool_*`
- Recommended exclude set:
  - `auth.json`
  - `log/`
  - `snapshot/`
  - `opencode.db-shm`
  - `storage/migration`
  - `bin/`
- Add focused tests proving OpenCode raw update retains DB, WAL when present, session diffs, and tool output, while excluding auth, logs, snapshots, SHM, migration markers, and runtime/package files.
- After code policy lands, prune committed Chatlas raw for excluded OpenCode files. Current HEAD has obvious over-retention: `auth.json`, `23` log files, `1100` snapshot files, and `storage/migration`.
- Prefer a follow-up SQLite-aware copy design so a future policy can retain a checkpointed/snapshotted `opencode.db` and exclude `opencode.db-wal` as runtime state.
