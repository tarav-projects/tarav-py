## The account monitor stopped fetching

The User reported that `tarav agent accounts monitor` was failing to fetch new
data. Every row showed `[Errno 24] Too many open files`. The running monitor
held 250 `/dev/ptmx` descriptors: since Oct 20 a half-installed `claude`
binary failed with `Exec format error`, and each Claude statusline refresh
opened a pty and leaked its master when `Popen` raised. The fix closes the
master on a failed spawn, with a regression test (`5e014e4`).

## codex/br showed another account's quota

The User saw codex/br at about 55% while the account's 5h window was empty.
The `app_server` fetch for br was correct (100%). The Codex session hook in
`~/.codex` writes `session_hook` records labelled `br` whose payload is jp's
quota, and the monitor takes the newest record from any source, so br
alternates between both. Not fixed yet; recorded in `notes/live/952`.

## Agent subsystem integration and Agentos cleanup

Asked how well the old agent system fits recent Tarav, the session found it
cleanly layered but barely integrated: one Tarav Type, no Checks, its own config
loader, Agentos names throughout, and thin tests. The User asked to integrate
it more without losing functionality and to clean the Agentos leftovers;
Impl.Req `notes/live/952` carried it in four slices. See
[agent-subsystem](../agent-subsystem.md).
